# 08. CI на GitHub Actions

Залежить від: 03. Оцінка: S.

## Мета

Кожен push у `develop` і кожен pull request автоматично проходять ruff, mypy і швидкі тести на Windows.

## Контекст

- Репозиторій: `github.com/ruslan-rv-ua/PyRetort`, гілка за замовчуванням `develop`, workflow-файлів немає; у `.github/` лише `copilot-instructions.md`.
- Проєкт працює лише на Windows (перевірка платформи в `src/pyretort/cli/__init__.py:21-27`, залежність `pywin32`), тому runner — `windows-latest`. Shell за замовчуванням для `run` на Windows-runner — PowerShell.
- `.python-version` = `3.13`; `uv.lock` у репозиторії.
- Актуальні версії дій (перевірено 7 жовтня 2026 за README репозиторіїв): `actions/checkout@v7`, `astral-sh/setup-uv@v10` (входи: `version`, `enable-cache`, `python-version`, `cache-dependency-glob`; `python-version` задає `UV_PYTHON`, і uv сам ставить потрібний Python).
- Швидкі тести — `uv run pytest` (без `slow`); повільні потребують мережі й довгі, у CI за замовчуванням не йдуть.

## Рішення

Файл `.github/workflows/ci.yml`:

```yaml
name: CI

on:
  push:
    branches: [develop]
  pull_request:
  workflow_dispatch:

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  checks:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v7
      - uses: astral-sh/setup-uv@v10
        with:
          python-version: "3.13"
          enable-cache: true
      - run: uv sync --locked
      - run: uv run ruff check src tests
      - run: uv run ruff format --check src tests
      - run: uv run mypy src
      - run: uv run pytest
```

`uv sync --locked` падає, якщо `uv.lock` розійшовся з `pyproject.toml`, і це бажано. Окремого job для e2e немає: він запускається вручну локально (задача 07); за потреби пізніше додати job з умовою `github.event_name == 'workflow_dispatch'`.

## Сіми

Тестів немає. Перевірка — синтаксис YAML локально і зелений прогін на GitHub після push.

## Кроки

1. Створити файл. Перевірити YAML: `uv run --no-project --with pyyaml python -c "import yaml; yaml.safe_load(open('.github/workflows/ci.yml'))"`.
2. Переконатися локально, що п'ять команд із job проходять: `uv sync --locked` і чотири перевірки.
3. Закомітити. Попросити користувача зробити `git push` (або отримати дозвіл і зробити самому), потім подивитися прогін: `gh run list --workflow ci.yml --limit 1` і `gh run view --log-failed` при збої. Якщо `gh` не встановлено — вкладка Actions у браузері.
4. Якщо прогін червоний через середовище runner'а, а не через код — виправити workflow і повторити.

## Критерій завершення

- `.github/workflows/ci.yml` у репозиторії з вмістом вище (мажорні версії дій можна підняти, якщо вийшли новіші, перевіривши README дії).
- Перший прогін на GitHub зелений; посилання на нього згадано у повідомленні коміту або в PR.
- Статус у README → DONE.
